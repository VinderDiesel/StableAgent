# StableAgent 技术推文系列大纲

> **状态：Current。** 本目录是对外技术文章的索引与选题规划。文章讲**已交付能力与实现特点**，不讲内部排期、阶段编号或里程碑。证据链（ADR / Acceptance / benchmark）用相对链接引用即可，正文避免「P2 / P3 / 下一阶段」等工程内部用语。**正文以可复用的设计原理为主，避免与具体项目决策强绑定**（见下方写作公约第 8 条）。

面向两类读者：

1. **想用 StableAgent 的人**：搞清它解决什么、怎么接、默认行为是什么。
2. **想学 Agent 系统的人**：借稳定实现看清底层原理、设计规范与常见踩坑，而不只是「调通一个 demo」。

叙事原则：**先建立最小心智模型，再按「可靠性 → 效率 → 协作 → 安全」逐层加深**；每篇只讲一个问题，用可复现的招牌动作（命令 / 测试 / 数字）收口，而不是概念清单。

## 各篇重点与写法

### 00 · 开篇：从 Demo Agent 到生产 Runtime

**一个问题**：为什么大多数 Agent 框架在 demo 里很炫，一进生产就碎？

**讲清楚**：

- 生产事故三类：进程死了、上下文爆了、对外部世界做了两遍或没做。
- StableAgent 的定位：轻量 Python Agent **运行时**——可靠执行 + 可测量上下文，而不是又一个「大而全应用」。
- 两层心智模型（不讲排期）：**Core Worker**（单任务推理循环 / 快照 / 上下文）与 **控制平面**（Ticket / Outbox / 授权 / 多 Worker）。
- 招牌动作预告：`SIGKILL` 后续跑、`provider_calls` 恰为剩余步数。

**入门价值**：建立「Agent = 带副作用的状态机」直觉，后面每篇都挂在这个模型上。

### 01 · Checkpoint（已有）

**一个问题**：进程被打死，怎么接着跑且不重做已完成的工作？

**讲清楚**：保存点选在步边界；回看落盘 vs 前看；崩溃窗口与工具可重入；版本迁移宁可不猜；存储协议小而可换。

**入门价值**：理解「快照恢复」相对「事件溯源重放」在 Agent 场景为何更合适。

### 02 · Context Engineering（已有）

**一个问题**：长任务怎么控 token，还不把正确性砍掉？

**讲清楚**：预算对象是组装后的 messages + tools；三种策略与事实保留率；resident 工具不可被筛掉；预算拒绝是正常结果。

**入门价值**：Context Engineering 不是 prompt 技巧，而是**可验收的运行时能力**。

### 03 · Durable Outbox（已有）

**一个问题**：状态能回滚，世界不能——副作用怎么既不丢也不重？

**讲清楚**：同事务写入状态与 effect；幂等键是命题不是身份证；事务内禁止 await；内存队列不是事实源。

**入门价值**：把分布式系统里的 outbox 模式迁移到 Agent 副作用治理。

### 04 · Agent Loop 与事件流契约（已有）

**一个问题**：为什么 checkpoint / context / 编排都能叠在 loop 上而不改内核？

**讲清楚**：

- `AgentState` 是唯一事实源且可无损序列化；I/O 全走注入接口，循环不持跨步记忆。
- `advance(state) -> (AgentState, list[Event])` 是**副本式状态转移**（不是数学纯函数）；`drive` 产出 `(事件, 事件后快照)` 对，把存盘点收敛到步边界。
- 事件契约：一次完整运行恰一个终止事件且居尾；`PAUSED` 不是终止；终止态静默落盘。
- 两个注入位点（assemble / select）默认原样透传，默认配置不建可选引擎；给内核开新入口优先用默认 `None` 的可选参数。
- 招牌动作：默认事件流逐字节比对 + 内核内容哈希锁定，证明"新能力没碰默认路径"。

**入门价值**：读懂「契约优先」：先锁执行模型，再长可选能力；并讲清替代方案（事件溯源 / hook 体系 / 模板方法 / 细粒度流式 / fork 内核）各自的适用边界。素材：[ADR-01](../design-decisions/01-loop-runtime.md)、[Contracts](../design-decisions/00-contracts.md)。

### 05 · 失败自愈（待写）

**一个问题**：这次调用失败了，该重试、换 Provider，还是停下来等人？

**讲清楚**：分类优先级（HTTP > 异常类型 > 文本特征 > 默认不可重试）；指数退避；fallback 轮转；`needs_human` 停在 `PAUSED`；sleep 可注入以便测试。

**入门价值**：把「韧性」从运气改成策略表。可与 01 互补：01 管进程死亡，05 管调用失败。素材散见 ADR-02 失败分类节。

### 06 · Ticket 编排（待写）

**一个问题**：一个长期目标如何拆成多次 Worker 执行，且整体仍可恢复？

**讲清楚**：Ticket 是跨 run 的工作单元；Assignment 绑定一次 Worker；Scheduler 门控（在途去重 / 依赖 / 槽位）；Event → Report 映射纪律；编排层不复制 Core 快照。

**入门价值**：区分「单 Worker 可靠」与「多任务协作可靠」。与 03 搭配：03 讲 effect 机制，06 讲领域状态机。素材：[ADR-04](../design-decisions/04-ticket-orchestration.md)。

### 07 · 受控执行（待写，能力就绪后发布）

**一个问题**：Agent 能跑命令、改仓库时，边界在哪里？

**讲清楚**：argv 数组而非 shell 字符串；精确白名单；工作目录 / worktree 隔离；Mandate 授权与审计；隔离 ≠ 安全边界（还需独立验证 sandbox）。

**入门价值**：把「Agent 动手」从默认放开改成默认可审计。仅在对应能力验收后再写完成时态。

### 08 · 设计规范与踩坑手册（待写）

**一个问题**：跨主题反复出现的规则，能不能收成一张清单？

**建议结构**（每条附「反例故障」）：

| 规范 | 一句话 |
|---|---|
| 状态完整边界才可存点 | 任意时刻切开的状态没有定义 |
| 默认路径保持安静 | 可选能力不得改变默认事件流 / 性能 |
| 状态与副作用同事务 | 先做后记 / 先记后做都会在崩溃缝里翻车 |
| 幂等键是命题 | 恢复路径换键还是复用键，选错表现为静默卡死 |
| 版本不明宁可报错 | 不要把语义漂移写进生产数据 |
| 不从文本猜类型 | 状态机只读结构化字段 |
| 金标准护默认路径 | 给 Core 开小口时用逐字节比对作证 |
| 测恢复先于测性能 | 架构分叉不是调参问题 |

**入门价值**：读完系列后的「可携带清单」，适合收藏与内部分享。

### 09 · 动手：从 Hello World 到可恢复任务（待写）

**一个问题**：最短路径怎么跑起来，并亲眼看到恢复？

**讲清楚**：无 API key 的脚本 Provider 示例 → 打开 checkpoint → 跑 selftest → 对照读 01/02。只给一条主路径，旁支链到深度文。

**入门价值**：降低第一公里摩擦；深度文负责「为什么」，本篇负责「先看见」。

## 如何深入浅出（写作公约）

1. **一篇一个招牌动作**。例如 01 的 `SIGKILL` + `provider_calls=2`；03 的「恰为 3 次 Provider 调用」。口号必须能被命令或测试证伪。
2. **先直觉错误，再给正确设计**。「每秒存一次」「先做再记」比直接抛术语更利于入门。
3. **代价写进正文**。每个决策至少一句「换来什么 / 付出什么」，避免神话化。
4. **数字带口径**。环境、参数、中位数、波动；效率指标与质量指标成对出现。
5. **术语稳定**。同一概念全系列只用一个中文名 + 一个英文符号（如「步边界 / step boundary」「幂等键 / idempotency_key」）。
6. **不写内部排期**。不出现阶段编号、里程碑、DoD 勾选进度；需要指向演进时链 [Roadmap](../Roadmap.md)，正文仍谈能力。
7. **草稿显式 Draft**。未补齐图示或真实模型数据前，不暗示为已发布承诺。
8. **正文讲原理，不与项目决策强绑定**。避免「ADR-04 决策 4.1」「验收账本 C3」「被否决方案第 N 条」这类把读者拽进本项目内部文档树的表达；代码与数据可作**示意**，但不得依赖读者去翻内部决策文件才读懂。每篇至少覆盖四问：**解决了什么问题 → 如何解决的 → 为什么这么解决（不这么做会怎样）→ 有没有更好 / 更省的替代方案**。把「为什么是它」讲透，而非只陈述「我们选了 X」。
